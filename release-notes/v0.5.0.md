## Highlights

- Chat can run on OpenAI, Anthropic, OpenRouter, Azure OpenAI and Microsoft Foundry, Amazon Bedrock, Google Vertex AI, or a self-hosted OpenAI-compatible server such as vLLM, Ollama, LM Studio, TGI or LiteLLM. Administrators choose the provider and model for each tier in a new **Models** tab and test them from the admin portal. Credentials stay in environment variables. ([Model providers](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/model-providers.md), [#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- People can reopen, search and delete their own past conversations. A **Not helpful** rating asks for a reason. Administrators can group questions into topics, receive a weekly Slack digest, see an estimated cost and set a monthly AI chat allowance per group. ([Saved conversations and privacy](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/accounts.md#saved-conversations-and-privacy), [#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- The template now includes browser tests that run the app against local stand-ins for MotherDuck and the model. CI runs them without secrets. ([#9](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/9))

## Upgrading from v0.4

This release is a minor version under the pre-1.0 policy, and it includes breaking changes. Deployments pinned to `v0.4.x` do not receive it automatically.

1. Fetch the `v0.5.0` tag and merge it into a new branch, keeping the local Dives, `dives.config.mjs` entries and branding. The steps are in [AGENTS.md](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/AGENTS.md#upgrade-a-copy-to-a-newer-template-version).
2. Rename `OPENAI_MODEL` to `CHAT_DEFAULT_MODEL` and `OPENAI_CHAT_MODELS` to `CHAT_MODELS` in the secret manager or host, if either is set. The previous names are no longer read.
3. On hosts other than Vercel, change the scheduled call from `/api/cron/access-sync` to `/api/cron/daily`. On Vercel, the merged `vercel.json` already does this. The daily run needs `CRON_SECRET`.
4. Run `npm ci`, then run `npm run db:migrate` before deploying. It adds the new columns and the `app_setting` table.
5. Run `npm test` and `npm run build`. Then check sign-in, the Dive, a chat answer and, in accounts mode, the **Models** and **Questions** tabs in a browser before deploying.

Review the [Compatibility](#compatibility) section for the other changes.

## Features

- Model providers ([Model providers](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/model-providers.md), [#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8)):
  - Each chat tier and the utility model can use OpenAI, Anthropic, OpenRouter, Azure OpenAI and Microsoft Foundry, Amazon Bedrock, Google Vertex AI or an OpenAI-compatible endpoint.
  - The setup check lists the variables that the chosen provider needs.
  - A key is sent only to its provider's own host, or to the base URL set beside it in the environment, never to an address entered in the portal.
- **Models** tab in the admin portal ([The admin Models tab](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/model-providers.md#the-admin-models-tab), [#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8)):
  - A quick setup applies one provider to every tier. Each tier can also set its own provider, model and endpoint.
  - Environment variables are shown only as set or missing.
  - **Test** sends a short prompt with a tool call and reports whether the model answered and called the tool.
  - Saved choices take precedence over environment variables. Saves and resets are recorded in **Activity**.
- Conversation history and ratings ([Saved conversations and privacy](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/accounts.md#saved-conversations-and-privacy), [#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8)):
  - **Past conversations** in the chat header lists a person's own saved conversations for the current Dive, with search and delete. A new question continues the conversation that was opened.
  - After **Not helpful**, the panel asks for a reason and an optional note.
  - A stopped answer keeps the text streamed before it was stopped.
- Question insights ([The admin portal](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/accounts.md#the-admin-portal), [#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8)):
  - **Group into topics** labels questions with the utility model and flags answers that said the data was not available.
  - Group managers see the **Questions** tab for the groups they manage.
  - An estimated cost tile in **Questions**.
  - A weekly Slack digest of questions, sent to `DIGEST_WEBHOOK_URL`, with **Send digest now** for an immediate post. ([Weekly digest](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/accounts.md#weekly-digest))
- A group can have a monthly AI chat allowance in tokens. Members are told when it resets once it is used up. ([Serve your customers](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/accounts.md#serve-your-customers), [#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- The optional `MOTHERDUCK_API_URL` setting sends the server's MotherDuck REST calls to another address. The end-to-end tests use it. Real deployments leave it unset. ([Configuration reference](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/configuration.md#dashboard-embedded-dive), [#9](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/9))

## Bug Fixes

- The weekly digest now covers every question since the previous digest. Previously, it covered a fixed seven days, so questions asked during part of Monday were missed and a week whose post failed was never sent. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- `CHAT_RETENTION_DAYS` is now enforced on every daily run. Previously, old messages were deleted only occasionally, after a small share of answers. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- The MotherDuck access sync now renews its lease during long runs, so a second server instance no longer starts a run while the first is still working. In manual mode, grants made by other people are no longer treated as the app's own. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- Deleting a person now also removes their group memberships and setup links. Previously, these rows remained in the app database. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- A person whose AI chat access is not recorded is now denied chat. Previously, a missing value allowed chat. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- The session refresh every 7.5 hours no longer reloads the whole app, so an open Dive and chat stay in place. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- The admin portal no longer creates a group twice on a double click. Slow requests that a newer request replaces are now cancelled, so they can no longer overwrite the newer result. A failed reload now shows an error instead of failing silently. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- Focused selection menus now show a visible focus ring. Chat answers no longer load remote images or follow unsafe links. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- The `chat_questions` view is faster on large app databases. With about 40,000 questions, a query previously took several seconds. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))

## Compatibility

- `OPENAI_MODEL` and `OPENAI_CHAT_MODELS` are removed. Use `CHAT_DEFAULT_MODEL` and `CHAT_MODELS`. See [Upgrading from v0.4](#upgrading-from-v04). ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- The scheduled route `/api/cron/access-sync` is replaced by `/api/cron/daily`, which runs the access sync and the retention cleanup. Schedulers outside Vercel must call the new path with `CRON_SECRET`. ([Saved conversations and privacy](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/accounts.md#saved-conversations-and-privacy), [#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- `CHAT_RETENTION_DAYS` now depends on the daily scheduled run. Deployments that set it must schedule `/api/cron/daily` and set `CRON_SECRET`. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- `npm run db:migrate` is required. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- The `chat_questions` view now pairs each question with its answer only through the answer's link to its question. Answers saved before v0.4.0 have no such link, so their questions appear without an answer or an outcome. Reports that cover that period should take this into account. ([Track questions in MotherDuck](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/accounts.md#track-questions-in-motherduck), [#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- `/api/embed` accepts only `POST`. The included app already used `POST`. Custom integrations that requested embed sessions with `GET` must send a `POST` with a JSON body naming the Dive. ([#9](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/9))
- The `npm run smoke:openai` script is removed. `npm run --silent setup -- --live --json` checks model access for OpenAI and Anthropic, and the **Test** button in **Models** checks any provider. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- Server routes are now native Next.js route handlers. The top-level `api/` directory is removed. Copies that added their own handlers there should move them to `app/api/`. ([Architecture](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.5.0/docs/architecture.md), [#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))

## Maintenance

- End-to-end tests ([#9](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/9)):
  - `npm run test:e2e` runs 18 Playwright tests in Chromium against stand-ins for the MotherDuck API, the embedded Dive and the model. They need no credentials.
  - The tests cover sign-in and sign-out, embed sessions and the Dive state, theme changes, blocked links, recovery when MotherDuck cannot open a Dive, streaming answers, the model picker, Stop, Retry, Clear, a separate conversation per Dive and a phone-sized viewport.
  - CI runs the suite and keeps the report and traces when a test fails.
- CI runs the checks on Node.js 24 and 26, with a time limit, and cancels runs that a newer push replaces. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- The app database tables are declared in one place, and new nullable columns are added by `npm run db:migrate` automatically. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- Deprecated AI SDK and zod calls are replaced. Unused components, exports and styles are removed. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- New unit tests cover the scheduled routes, administrator and manager access, conversation ownership, cleanup after a person is deleted, the content security policy, the sign-in throttle, digest periods, bulk import, daily retention and the model providers. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8))
- New documentation covers model providers, the **Models** tab and the end-to-end tests. ([#8](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/8), [#9](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/9))
