## Highlights

- Groups with their own MotherDuck service account now keep each customer's data fully apart. Every member gets exactly the group's Dives and chat, and the service account is granted only the group's Dives. Previously, one member's own access could widen what the whole group's service account could read. ([Groups](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.3.0/docs/accounts.md#the-admin-portal), [#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Group managers, setup links, single sign-on and the MotherDuck access sync have been hardened following two security reviews. Managers act only on people who belong to nothing but the groups they manage, single sign-on uses only verified emails, and the access sync never loses, repeats or misattributes a change. ([Group managers](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.3.0/docs/accounts.md#group-managers), [#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- The admin portal adds an activity log of every change, invitation and sign-in status for each person, CSV export, confirmations before consequential changes and self-service password changes. Single sign-on can place people into a group by email domain on their first sign-in. ([Admin portal](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.3.0/docs/accounts.md#the-admin-portal), [#6](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/6))

## Upgrading from v0.2

This release is a minor version because it adds features and changes how access is computed for groups with a service account, how single sign-on treats unverified emails, and what group managers may do. Deployments pinned to `v0.2.x` do not receive it automatically.

1. Fetch the `v0.3.0` tag and merge it into a new branch, keeping the local Dives, `dives.config.mjs` entries and branding. The steps are in [AGENTS.md](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.3.0/AGENTS.md#upgrade-a-copy-to-a-newer-template-version).
2. Run `npm ci`.
3. Run `npm run db:migrate`. It adds the `app_lock` and `audit_event` tables and the `lastSignInAt` column. The app keeps working before the migration, without the activity log and the cross-instance sync lock.
4. Review the single sign-on settings against the [Compatibility](#compatibility) section. Deployments that use a generic OpenID Connect provider that does not send `email_verified` should set `SSO_TRUSTED=true` only when that provider is the organization's own directory.
5. On Vercel, set `CRON_SECRET` to enable the daily access check.
6. Run `npm test` and `npm run build`, then check the admin portal and a group member's session in a browser before deploying.

Review these changes in the [Compatibility](#compatibility) section: access in groups with a service account, verified emails for single sign-on, the narrower scope of group managers and the new arguments for **Mark as done**.

## Features

- Activity log ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5), [#6](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/6)):
  - The new **Activity** tab lists who changed what, newest first, and filters by person or by kind of change.
  - It records people added, access changes, disabling and re-enabling, setup links, passwords set or changed, role changes, deletions, impersonation, group changes and memberships, service accounts created, MotherDuck syncs and deleted conversations.
  - Entries never contain passwords, setup links or tokens. An administrator acting while impersonating someone is recorded under their own name.
- People ([#6](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/6)):
  - Each person shows whether a setup link is waiting and until when, whether it expired, when the person last signed in, and whether they sign in with single sign-on.
  - **Export CSV** downloads everyone with their role, groups, MotherDuck username and last sign-in. **Find people** also matches group names.
  - **Make admin**, **Disable**, **Delete** and **Delete group** ask for confirmation in place. **Delete group** states how many members lose the group's access.
  - A pasted list shows how many people it contains and is refused before sending when it exceeds 200.
  - Server errors are shown as plain sentences rather than error codes.
- Self-service passwords: **Change password** in the sidebar lets people with a password change it, which signs them out everywhere else. People who sign in with single sign-on are directed to their identity provider. ([#6](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/6))
- Groups ([#6](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/6)):
  - Each group card states whether AI chat works for its members, and why not when the admin token or the chat database is missing.
  - With `MOTHERDUCK_ADMIN_TOKEN`, saving a group with a new service account name can create the account in MotherDuck in the same step.
  - Adding members to a group can be filtered by name in large organizations.
  - Group managers see what each of their groups can open.
- Single sign-on ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5)):
  - `AUTH_DOMAIN_GROUPS` places people whose verified email is at a listed domain into the named group when single sign-on creates their account, with no access of their own. ([Who single sign-on lets in](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.3.0/docs/accounts.md#who-single-sign-on-lets-in))
  - `AUTH_NEW_ACCOUNT_ACCESS=none` starts accounts that single sign-on creates with no access until an administrator grants it.
- MotherDuck access sync ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5)):
  - In manual mode, the SQL now includes `REVOKE` and `DETACH` statements when access is removed, and **Mark as done** settles exactly the changes in the SQL shown on screen.
  - On Vercel, `/api/cron/access-sync` runs once a day when `CRON_SECRET` is set, and corrects grants changed outside the app or left by a failed sync.
  - Removing a person through any administrator action, including role changes and deletion, starts a sync on the server.
  - The **Sync now** button reports when another sync is already running and will include the change.

## Bug Fixes

- Previously, a member of a group with a service account could have their own Dives, or another group's Dives, added to what the shared service account was granted and attached, which made that data readable through chat by every member of the group. The group alone now decides, and the service account is granted only the group's Dives. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, a person removed from a customer group could fall back to their own default access to every Dive. Joining a group with a service account now clears the person's own access. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, a group manager could create a setup link for anyone in a managed group, including people who also belonged to other groups, managed another group, signed in with single sign-on or later became administrators, and could then sign in as them. Managers now act only on people who belong to nothing but their groups, and every setup link is checked again against its creator when it is used. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, a group manager could re-enable someone an administrator had disabled. This is now refused, including by disabling the person again first. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, single sign-on could link to, or create, an account for an email that the identity provider had not verified. Single sign-on now requires a verified email, except for Okta, a single Microsoft Entra ID tenant and a generic provider marked with `SSO_TRUSTED=true`. Previously, single sign-on also never linked to accounts created by administrators. Emails entered by administrators now count as verified, so linking works. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, sign-in attempts were not limited on hosts other than Vercel unless `AUTH_TRUSTED_IP_HEADER` was set. Sign-in now allows ten failed attempts per account every ten minutes on every host. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, manual mode never listed a `REVOKE` and kept listing a `GRANT` that had already been run. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, pointing a Dive alias at another share, or swapping two aliases, could leave a share detached while it was recorded as synced. All moving aliases are now detached before any attach. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, syncs on separate server instances could run at the same time and record a grant as pre-existing, so it was never revoked. One sync now runs at a time across instances, and grant records are saved in a single statement. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, an existing database alias on a service account could be recorded as attached by the app and later detached. It is now left in place. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, the chat SQL guard allowed the spatial file readers (`ST_Read` and related functions) and settings functions such as `current_setting`. These, and the `pg_settings`, `duckdb_settings` and `duckdb_secrets` views, are now refused. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, group member counts included deleted people, a group card showed AI chat as on when it could not work, **Create it in MotherDuck** reported "Copied" on success, and people added with a password were announced as "Copied". These now show the correct state. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5), [#6](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/6))
- Previously, two groups could share one service account and therefore read each other's data. This is now refused. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, a public demo showed share URLs in **MotherDuck access**. A public demo now shows share names only. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5))
- Previously, the People list was cut at the newest 1,000 accounts before a manager's view was filtered, so a manager could see an empty list. A manager's list is now filtered in the database, and administrators are told when the list is limited. ([#5](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/5), [#6](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/6))

## Compatibility

- **Groups with a service account.** Members now receive exactly that group's Dives and chat. Their own access and other groups no longer add to it. Joining such a group, or giving an existing group a service account, clears the members' own access. Administrators who relied on personal access for members of such groups should grant those Dives to the group instead.
- **Single sign-on requires verified emails.** Accounts are created, and linked to accounts that administrators created, only when the identity provider reports the email as verified. Okta and a single Microsoft Entra ID tenant are trusted without that claim. A generic OpenID Connect provider that does not send `email_verified` requires `SSO_TRUSTED=true`, which should be set only when the provider is the organization's own directory.
- **Group managers.** Managers can no longer act on people who also belong to another group, who manage a group, or who are administrators. While single sign-on is configured, managers cannot create setup links for people whose email an administrator entered. Unused setup links created by a manager stop working when the person moves out of that manager's reach. Disabling a person cancels their unused setup links.
- **Mark as done.** `POST /api/admin/access-sync` with `{ "confirm": true }` is replaced by `{ "confirm": [{ "grantee", "url" }] }`, which lists the changes the share owner ran. The admin portal sends this list. Scripts that called the previous form must send the `planned` list from `GET /api/admin/access-sync`.
- **Sign-in limits.** Ten failed sign-ins per account within ten minutes return HTTP 429 for that account for the rest of the window, on every host.
- **Database.** `npm run db:migrate` is required for the activity log, the sync lock and the last sign-in time.
- **Settings.** New optional settings are `AUTH_DOMAIN_GROUPS`, `AUTH_NEW_ACCOUNT_ACCESS`, `SSO_TRUSTED` and `CRON_SECRET`. ([Configuration](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.3.0/docs/configuration.md))
- `vercel.json` now declares a daily cron job for `/api/cron/access-sync`. The route does nothing until `CRON_SECRET` is set.
