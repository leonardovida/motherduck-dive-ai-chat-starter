## Highlights

- Two groups can no longer share a name. Single sign-on domain groups find a group by name, so a duplicate name could place a new person in another customer's group. ([#14](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/14))
- The **Activity** tab can no longer fail because of one unreadable entry, and its search treats `_` and `%` as plain characters. ([#13](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/13))
- **Retry** after a dropped connection no longer saves the question twice, and the **Questions** chart counts each question on its UTC day. ([#13](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/13), [#14](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/14))

## Upgrading from v0.6.1

This release is a patch version. Deployments that allow `~0.6.0` or `^0.6.0` receive it. It adds no settings and no database changes, so `npm run db:migrate` is not required.

1. Fetch the `v0.6.2` tag and merge it into a new branch, keeping the local Dives, `dives.config.mjs` entries and branding. The steps are in [AGENTS.md](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.2/AGENTS.md#upgrade-a-copy-to-a-newer-release).
2. Run `npm ci`, `npm test` and `npm run build`.
3. Deployments on AWS, Google Cloud or Azure that pin the image change the tag to `0.6.2`, as described in each cloud's **Upgrade** section of [docs/deploy.md](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.2/docs/deploy.md).
4. Review the [Compatibility](#compatibility) section.

## Bug Fixes

- Groups ([#14](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/14)):
  - Two groups could have the same name, including names that differ only in case. `AUTH_DOMAIN_GROUPS` then placed new single sign-on users in whichever of them came first, which could be another customer's group with its own MotherDuck service account. The **Questions** filters also combined such groups. A group can no longer be created or renamed to a name that another group uses.
- **Questions** tab ([#14](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/14)):
  - The daily chart grouped questions by day in the database session's time zone, while the chart shows UTC days. With a session outside UTC, questions appeared on the wrong day, and questions near the start of the window could be left out. Questions are now counted on their UTC day.
- **Activity** tab ([#13](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/13)):
  - A change detail longer than 4,000 characters was cut off and stored as invalid JSON, which made the whole Activity list fail to load. Such details are now stored as a short note, and an entry that cannot be read shows no detail instead of failing the list.
  - The person search treated `_` and `%` in a search as wildcards, so a search for a username that contains `_` also matched other people. Both characters are now matched literally.
- Chat ([#13](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/13)):
  - When the connection dropped during an answer, the answer was saved as stopped and the browser offered **Retry**. Retry then saved the question a second time. It now reuses the question and replaces the stopped answer, as it already did for a failed one.

## Compatibility

- Creating or renaming a group to a name that another group already uses, ignoring case, now returns 409 with `group_name_taken`. Existing groups with duplicate names keep working. Rename one of them so that single sign-on domain groups and the **Questions** filters can tell them apart.
