## Highlights

- The starter now runs in an organization's own AWS, Google Cloud or Azure account, from a prebuilt container image. Each cloud has a one-click path and a repeatable infrastructure-as-code path. Secrets stay in that cloud's secret manager, `APP_URL` is set automatically and the daily and weekly scheduled calls are created. ([Deploy to AWS, Google Cloud or Azure](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/deploy.md), [#11](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/11))
- Each release publishes a container image to GitHub Container Registry, which also runs on any other container host. ([The container image](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/deploy.md#the-container-image), [#11](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/11))
- The repository is no longer a GitHub template. Forks and clones keep the shared Git history, so later releases merge in with `git merge`. ([Use a specific version](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/releasing.md#use-a-specific-version))

## Upgrading from v0.5

This release is a minor version under the pre-1.0 policy. Deployments that allow `^0.5.0` or `~0.5.1` do not receive it automatically. It adds no settings and no database changes, so `npm run db:migrate` is not required, and existing Vercel deployments build as before.

1. Fetch the `v0.6.0` tag and merge it into a new branch, keeping the local Dives, `dives.config.mjs` entries and branding. The steps are in [AGENTS.md](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/AGENTS.md#upgrade-a-copy-to-a-newer-release).
2. Run `npm ci`, `npm test` and `npm run build`.
3. To move a deployment to AWS, Google Cloud or Azure, follow [docs/deploy.md](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/deploy.md), starting with [Choose how people sign in](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/deploy.md#choose-how-people-sign-in).

Review the [Compatibility](#compatibility) section before upgrading.

## Features

- Container image ([The container image](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/deploy.md#the-container-image), [#11](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/11)):
  - A `Dockerfile` builds a self-contained Next.js server that runs as a non-root user.
  - Each release tag publishes `ghcr.io/leonardovida/motherduck-dive-ai-chat-starter` with the version number and, for a release without a suffix, `latest`.
  - `deploy/cron.mjs` calls the daily and weekly routes from a scheduled job, so `CRON_SECRET` stays in the platform's secret manager.
- AWS ([AWS](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/deploy.md#aws), [#11](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/11)):
  - The app runs on ECS Fargate behind an internal load balancer that only CloudFront can reach. CloudFront provides an HTTPS address without a custom domain.
  - A CloudFront Function overwrites the client IP header on every request, so the shared password and per-person accounts both work.
  - The stack deploys from the CloudFormation console with `deploy/aws/cloudformation.template.json`, or with the AWS CDK in `deploy/aws`. EventBridge Scheduler runs the scheduled calls.
- Google Cloud ([Google Cloud](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/deploy.md#google-cloud), [#11](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/11)):
  - The app runs on Cloud Run, with secrets in Secret Manager and Cloud Scheduler starting Cloud Run jobs for the scheduled calls.
  - The **Run on Google Cloud** button prompts for each secret with hidden input and deploys in accounts mode.
  - Terraform in `deploy/gcp/terraform` provides repeatable deployments. With a custom domain, it adds a load balancer that enables the shared password.
- Azure ([Azure](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/deploy.md#azure), [#11](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/11)):
  - The app runs on Azure Container Apps, with secrets in Key Vault, read through a managed identity, and scheduled Container Apps jobs for the scheduled calls.
  - The **Deploy to Azure** button deploys `deploy/azure/azuredeploy.json`. Repeatable deployments use `deploy/azure/main.bicep`.
- Coding agents follow a new section in AGENTS.md to deploy to these clouds. It asks for the cloud and sign-in mode, and keeps secret values out of command lines and configuration files. ([#11](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/pull/11))

## Compatibility

- The GitHub **Use this template** button is no longer available. New projects fork or clone the repository, which keeps the shared history needed for upgrades. Existing copies created from the template continue to work. Their next upgrade needs `git merge --allow-unrelated-histories` once. ([Use a specific version](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/releasing.md#use-a-specific-version))
- On Google Cloud without a custom domain, and on Azure, the shared password is refused in production because no proxy sets a trusted client IP header. These deployments use per-person accounts, which need `npm run db:migrate` and `npm run admin:create` to run once before the first deploy. ([Choose how people sign in](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.6.0/docs/deploy.md#choose-how-people-sign-in))
