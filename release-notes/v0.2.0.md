## Highlights

- An optional accounts mode replaces the shared demo password with per-person sign-in. It includes an admin portal for people, passwords and access to each Dive and to AI chat, and optional single sign-on through Okta, Microsoft Entra ID, Google, GitHub or any OpenID Connect provider. ([Accounts guide](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.2.0/docs/accounts.md))
- AI chat now works with Anthropic models as well as OpenAI models. The new default, Auto, sends simple questions to a smaller and less expensive model and harder questions to a larger one. ([Model routing guide](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.2.0/docs/model-routing.md))
- In accounts mode, administrators can review saved conversations, including the model that answered, the routing reason and the SQL that ran. People are told in the chat panel that conversations are saved. ([Accounts guide](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.2.0/docs/accounts.md#saved-conversations-and-privacy))

## Upgrading from v0.1

This release is a minor version because it adds features and changes the default chat model choice. Existing deployments continue to use the shared password until accounts mode is turned on.

1. Fetch the `v0.2.0` tag and merge it into a new branch, keeping the local Dives, `dives.config.mjs` entries and branding. The steps are in [AGENTS.md](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.2.0/AGENTS.md#upgrade-a-copy-to-a-newer-template-version).
2. Run `npm ci`.
3. Review the chat settings. `OPENAI_MODEL` and `OPENAI_CHAT_MODELS` continue to work. The new names are `CHAT_DEFAULT_MODEL` and `CHAT_MODELS`.
4. To keep a fixed model instead of Auto, set `CHAT_DEFAULT_MODEL` to a tier name, or set `CHAT_ROUTER=off`.
5. Run `npm run --silent setup -- --live --json`, `npm test` and `npm run build`, then check the chat in a browser before deploying.
6. To adopt accounts mode, follow the [accounts guide](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.2.0/docs/accounts.md#turn-it-on). It requires `MOTHERDUCK_APP_TOKEN`, `npm run db:migrate` and `npm run admin:create`.

Review the following changes in the [Compatibility](#compatibility) section: the Auto default, the renamed settings and the replacement of `DEMO_PASSWORD` in accounts mode.

## Features

- Accounts mode ([Accounts guide](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.2.0/docs/accounts.md)):
  - Accounts, sessions and conversations are stored in a MotherDuck database that the app owns, so no additional database service is required. Authentication uses the open-source Better Auth library.
  - `npm run db:migrate` creates the app database tables and can be run again after each upgrade. `npm run admin:create` creates the first administrator and can restore administrator access.
  - The admin portal at `/admin` adds people, sets passwords, limits each person to selected Dives, turns AI chat on or off for a person, assigns the administrator role, and disables or deletes accounts. Access changes and disabled accounts take effect on the next chat or Dive request.
  - The **Conversations** view filters by person and Dive, searches by first question, shows each answer with its model, provider, routing reason, token counts and SQL steps, and exports a conversation as JSON. Saved answers never include query result rows.
  - `CHAT_HISTORY=off` turns saving off, and `CHAT_RETENTION_DAYS` deletes older messages automatically.
  - `PUBLIC_DEMO=true` makes a deployment safe to share publicly with one sign-in. Visitors can open every screen, including the admin portal, but every change is switched off. Model tiers that are not enabled appear greyed out. ([Run a public demo](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.2.0/docs/accounts.md#run-a-public-demo))
- Single sign-on:
  - A generic OpenID Connect provider is configured with `SSO_ISSUER` or `SSO_DISCOVERY_URL`, and settings are also provided for Okta, Microsoft Entra ID, Google and GitHub.
  - By default, only people who already have an account can sign in with SSO. `AUTH_ALLOWED_EMAIL_DOMAINS` lets people from the listed domains receive an account on first sign-in.
- Models and routing ([Model routing guide](https://github.com/leonardovida/motherduck-dive-ai-chat-starter/blob/v0.2.0/docs/model-routing.md)):
  - `ANTHROPIC_API_KEY` enables Anthropic models. One provider key is sufficient, and both can be set.
  - Each of the three tiers (Luna, Sol and Astra) can be assigned to a provider and model with `CHAT_MODEL_LUNA`, `CHAT_MODEL_SOL` and `CHAT_MODEL_ASTRA`. `CHAT_PROVIDER` selects the default provider.
  - Auto routing decides with rules first, then with a short classification by the smallest model. During an answer, it moves to a larger model after failed tool calls or many steps.
  - Answers chosen by Auto show the tier, and the routing reason is available on hover and in the admin portal.
  - `OPENAI_BASE_URL` and `ANTHROPIC_BASE_URL` allow requests to go through a compatible gateway or an external router.
- The setup command reports the accounts settings and, with `--live`, checks the app database and access to the default Anthropic or OpenAI model.

## Compatibility

- Auto is now the default model choice when two or more tiers are enabled. Deployments that require a fixed model should set `CHAT_DEFAULT_MODEL` to a tier name or set `CHAT_ROUTER=off`.
- `OPENAI_MODEL` and `OPENAI_CHAT_MODELS` are deprecated in favor of `CHAT_DEFAULT_MODEL` and `CHAT_MODELS`. The previous names continue to work in this release.
- When `MOTHERDUCK_APP_TOKEN` is set, `DEMO_PASSWORD` is no longer accepted and sign-in requires an account. Production deployments in accounts mode require `SESSION_SECRET`, and hosts other than Vercel also require `APP_URL`.
- `MOTHERDUCK_APP_TOKEN` must be a read-write token scoped to the app database only. It must not be reused as the read-only chat token.
- Accounts mode supports the MotherDuck Postgres endpoint only. Better Auth's built-in migrator is not used, because MotherDuck does not provide the Postgres catalog functions it requires. `npm run db:migrate` manages the schema instead.
